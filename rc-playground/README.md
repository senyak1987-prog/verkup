# Маленький заезд

3D-мини-игра в стиле «Город Свет» работает в двух вариантах: во дворе здания в конфигураторе вывесок и на отдельной странице. Оба используют скачанную модель **Dodge RAM 1500 TRX** автора **DR1KING100K**, адаптированную до **99 812 треугольников**. Золотая окраска, тёмно-зелёные детали, раздельные материалы резины, дисков, стекла и фар дополняются логотипами «Город Свет» на обеих дверях и капоте. Модель и симуляция общие; геометрия площадки адаптируется к фасаду. Собственная HTML-точка входа входит в общую сборку Vite.

Исходник: [Dodge RAM 1500 TRX](https://sketchfab.com/3d-models/dodge-ram-1500-trx-d6d548c5fe9f4749813f0a386edfd42c) by [DR1KING100K](https://sketchfab.com/DR1KING100K), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Изменения: упрощение геометрии, нормализация масштаба, раздельные ступицы, материалы и фирменная окраска. Кредит автора виден в обоих игровых интерфейсах и сохранён в `public/models/ram-trx-attribution.txt`.

GLB загружается один раз, а каждый экземпляр игры получает собственные геометрию и материалы. Загрузка не сбрасывает движение или выбранный цвет; смена фасада и закрытие сцены освобождают запоздавшие экземпляры. Пока ресурс загружается или при ошибке доступна упрощённая машинка.

## Открыть

```sh
npm run dev -- --port 5174
```

При стандартном `VITE_BASE_PATH` откройте `http://localhost:5174/verkup/sign-configurator/`, выберите «Визуализация 3D», затем «Поиграть с машинкой». Площадка находится перед зданием с текущей вывеской. Заезд раскрывает существующее 3D-полотно на весь экран; «К вывеске» или Escape возвращает исходный ракурс и масштаб примерки. Выбранная вывеска, размещение и освещение сохраняются. В 2D игра недоступна.

Отдельная страница: `http://localhost:5174/verkup/rc-playground/`. При сборке с `VITE_BASE_PATH=/` адреса будут `/sign-configurator/` и `/rc-playground/`.

ЛКМ или касание: удерживайте и указывайте, куда ехать. Отпустите — машинка катится по инерции, автоматическое торможение к курсору отключается. ПКМ — обычный тормоз всех колёс. Пробел — ручник: задние колёса блокируются, передние продолжают вращаться, тянуть и рулить. Shift с ЛКМ — задний ход. WASD и стрелки работают после фокусировки полигона: W/вверх — газ, S/вниз — назад, A/D — руль. Пока газ удерживается, машинка плавно тормозит около курсора.

«Свободный заезд» позволяет исследовать полигон. «На время» запускает секундомер при первом нажатии газа: пройдите шесть ворот по порядку, активные ворота отмечены зелёным кругом. Лучшее время сохраняется на этом устройстве. «На старт» сбрасывает текущий заезд и возвращает все предметы на исходные места, сохраняя рекорд. Четыре камеры — «Полигон», «Следом», «Сзади» и «Детали» — работают также на паузе. «Сзади» даёт низкий ракурс за пикапом и смотрит вперёд по направлению движения.

В конфигураторе те же режимы называются «Свободно» и «На время»; доступны три камеры — «Площадка», «Машинка» и «Сзади». Кнопка паузы останавливает физику автомобиля, предметов и секундомер; сброс возвращает машинку на старт и восстанавливает предметы. Скрытая вкладка, невидимое полотно или потеря фокуса прерывают удерживаемое управление.

## Сцена конфигуратора

`SignScene3D.tsx` подключает `facadeGame.ts` к существующим сцене, ортографической камере, canvas и renderer. Вторая сцена, iframe и отдельный WebGL-контекст для заезда не создаются. На время игры обычное вращение примерки отключается, камера получает игровой ракурс; при выходе её состояние восстанавливается.

`world.ts` создаёт общую площадку, машинку и их визуальное состояние без камеры, renderer, обработчиков ввода или собственного цикла кадров. `game.ts` добавляет эти части для отдельной страницы и ES-модуля; `facadeGame.ts` использует уже работающий цикл конфигуратора. Пока заезд не запущен, площадка видна у здания, но её физика не выполняет шаги. Пауза также останавливает шаги симуляции.

`facadePlacement.ts` вычисляет положение по границам стены и тротуара в локальных координатах фасада, включая смещённые части углового здания. Масштаб — 200 мм на игровую единицу. Двор занимает полную ширину передней стены и соединяет существующий тротуар с площадкой глубиной 4400 мм перед ним. При смене варианта здания границы пересчитываются автоматически.

Три настоящие ступени входной лестницы и порог входят в общее поле высот: по ним можно заехать на верхнюю площадку. Дополнительный пол не закрывает лестницу. Клумбы и колонны козырька остаются неподвижными препятствиями для автомобиля и физических предметов. Игровые объекты не входят в геометрию вывески, её размеры и производственный экспорт.

## Встроить через iframe

Подставьте адрес опубликованной сборки. Никаких внешних скриптов или аккаунтов не требуется.

```html
<iframe
  src="/verkup/rc-playground/?embed=1"
  title="Мини-игра с радиоуправляемой машинкой"
  width="100%"
  height="560"
  loading="lazy"
  style="display:block;border:0;border-radius:16px"
></iframe>
```

Высота от 410 px. Встроенный режим убирает шапку страницы и нижние подсказки, сохраняя режимы, камеры, цвета и помощь. Если основная сборка размещена в корне, уберите `/verkup` из адреса. Для другого домена укажите полный URL игры.

## Отдельный виджет React

Для другого раздела сайта или отдельного виджета доступен React-компонент. Его CSS изолирован префиксом `rc-`. Импортировать игру лениво, когда пользователь её открывает:

```tsx
import { lazy, Suspense } from 'react';
const RcGame = lazy(() => import('../rc-game/RcGame').then(m => ({ default: m.RcGame })));

<div style={{ height: 560 }}>
  <Suspense fallback={<p>Загружаем машинку…</p>}>
    <RcGame embedded onLap={seconds => console.log('Круг:', seconds)} />
  </Suspense>
</div>
```

## ES-модуль для любого сайта

```sh
npm run build
npm run build:rc-embed
```

Второй шаг создаёт `dist/rc-embed/rc-game.js` с включёнными Three.js и Cannon ES и копирует рядом `ram-trx.glb` и атрибуцию. Выполняйте его после общей сборки, которая очищает `dist`. Модуль не зависит от React. Опубликуйте всю папку `rc-embed` вместе с сайтом и сохраните кредит автора модели:

```html
<div id="rc-car" style="width:100%;height:520px"></div>
<script type="module">
  import { mountRcGame } from '/verkup/rc-embed/rc-game.js';
  const game = mountRcGame(document.querySelector('#rc-car'), {
    onTelemetry: state => { /* speed: км/ч; elapsed/best: секунды */ },
    onLap: seconds => console.log('Круг:', seconds),
    onError: message => console.error(message),
    // vehicleUrl: '/custom-assets/ram-trx.glb', // необязательный другой адрес модели
  });
  game.setMode('trial'); // 'free' или 'trial'
  game.setCamera('rear'); // 'overview', 'follow', 'rear' или 'detail'
  game.setColor('#3a8667');
  // game.setPaused(true); game.reset();
  // При удалении виджета обязательно: game.destroy();
</script>
```

`mountRcGame` создаёт сцену, камеру и renderer без интерфейса управления: его можно оформить самостоятельно. `onTelemetry` вызывается примерно десять раз в секунду. Контейнер можно изменять без повторного монтирования. Каждый экземпляр имеет собственные события и физику; `destroy()` освобождает геометрию, материалы, текстуры, WebGL-контекст, observers и кадры. При невидимом контейнере или скрытой вкладке игра останавливается. Клавиатура перехватывается только на сфокусированном полигоне.

## Физика и проверки

TRX использует силы четырёх шин с полным приводом и распределением тяги 40:60 между передней и задней осями. Сцепление ограничено нагрузкой на каждое колесо и отличается на песке и брусчатке. Поворот кузова возникает от моментов контактных сил; боковая скорость сохраняется как занос. Ручник снижает боковое сцепление задней оси, после отпускания сцепление постепенно стабилизирует траекторию. Руль не ограничивает скорость принудительно. Пыль учитывает полную скорость скольжения, а следы остаются под двумя задними шинами.

В отображении скачанной модели исправляется ориентация треугольников относительно исходных нормалей, затем восстанавливаются сглаженные нормали с сохранением жёстких рёбер. Число треугольников остаётся прежним. На дверях и капоте используется оригинальный векторный wordmark из `public/gorod-svet-wordmark.svg` без подмены шрифта. Краска, резина, стекло и металлические детали имеют отдельные PBR-материалы; линзы фар используют физическое пропускание света вместо сортировки прозрачных оболочек. Персонаж-супергерой больше не загружается и не добавляется к фасаду.

У RAM TRX максимальная скорость увеличена втрое: ограничение 16,5 игровых единиц/с. Мотор и тормоза усилены; движение к курсору замедляется перед крутым поворотом и останавливается у цели. Высокие ступени машина проходит на пониженной скорости. Антенна длиной 2,7 игровых единицы сохраняет прежнюю тонкую нить и маленький наконечник; крепление уменьшено втрое.

Перед зданием находятся песчаный двор и тротуар из отдельных фасонных камней. Высоты камней и швы входят в поле контактов колёс и вызывают работу подвески. Пыль выходит только из нагруженных колёс на песке; фиксированный пул частиц освобождается вместе со сценой. Фары освещают землю, задние огни усиливаются при торможении. Динамическая тень двора рассчитывается каждый кадр отдельным источником с картой до 4096 × 4096, с учётом возможностей устройства. Архитектурная кешированная тень не содержит подвижных игровых объектов.

Автомобиль использует собственную игровую модель с фиксированным шагом 120 Гц: инерция, боковое сцепление, рулевая модель, тормоз и задний ход. Четыре независимых контакта с общим полем высот управляют пружинами и демпферами; корпус реагирует креном, тангажом и вертикальными колебаниями. Ограничители хода подвески поддерживают колёса над реальными ступенями и поднимают кузов при заезде на лестницу. Антенна — упругая цепь из десяти связанных сегментов с инерцией и ограничением длины.

`propsPhysics.ts` рассчитывает 53 независимых твёрдых тела в Cannon ES: десять конусов, девять покрышек в трёх стопках, двенадцать столбиков ворот, двенадцать ящиков, шесть бочек и четыре мяча. У каждого тела своя масса, положение, вращение и инерция; действуют гравитация, трение, столкновения с землёй, машинкой и другими предметами. Все покрышки имеют один размер, согласованный с радиусом колёс текущей машинки. Покрышки могут отделяться от стопки, катиться и опрокидываться; конусы и столбики отлетают и падают после удара. Физические силуэты покрышек сохраняют отверстие. Кинематический коллайдер кузова передаёт движение автомобиля в Cannon, а рассчитанный встречный импульс возвращается в модель автомобиля как отдача. На паузе обе симуляции останавливаются; сброс восстанавливает позиции и ориентации предметов, обнуляя линейную и угловую скорость.

Автомобиль и предметы используют разные решатели: контактная подвеска автомобиля не является полной моделью твёрдого тела Cannon. Кузов автомобиля не переворачивается и не деформируется; предметы имеют полноценное вращение твёрдых тел. Обе симуляции используют согласованную поверхность и шаг 120 Гц.

```sh
npm run test:rc-game
npm run test:rc-suspension
npm run test:rc-vehicle
npm run test:trx-asset
npm run test:rc-props
npm run test:facade-rc
npm run build
npm run build:rc-embed
```

Тесты автомобиля проверяют торможение, инерцию, цель мыши, задний ход, зависимость от FPS, перенос нагрузки, свободный полёт и приземление, ограничители хода, руление Ackermann, антенну, стены и длительную устойчивость. Проверки визуальной подвески подтверждают сохранение длины корпуса амортизатора при скольжении штока, сжатие пружин и соединение заднего моста с обеими ступицами. Тесты предметов проверяют движение и вращение каждого типа после удара, отдачу автомобилю, гравитацию, распад стопки шин, контакт с полем высот, точный сброс и устойчивость при разных FPS. Проверки размещения используют настоящие модели фасадов и подтверждают ширину двора, соединение с тротуаром, высоты ступеней и порога, сохранение видимой лестницы и заезд автомобиля на верхнюю ступень. Положение колёс проверяется тем же полным 3D-преобразованием, что и отображение кузова.

Браузерные проверки используют Vite на 5174 и отдельный тестовый Chrome с `--remote-debugging-port=9334`. Например, в PowerShell на Windows запустите Chrome с профилем вне репозитория:

```powershell
$rcTestProfile = Join-Path $env:TEMP 'codex-rc-playground-profile'
$rcChromeArgs = @(
  '--headless=new', '--no-first-run', '--no-default-browser-check',
  '--remote-debugging-address=127.0.0.1', '--remote-debugging-port=9334',
  ('--user-data-dir="' + $rcTestProfile + '"'), 'about:blank'
)
Start-Process 'C:\Program Files\Google\Chrome\Application\chrome.exe' -ArgumentList $rcChromeArgs -WindowStyle Hidden
```

Проверка отдельной игры проходит круг реальными событиями мыши, проверяет касания, паузу, сброс, камеру деталей, встраивание и загрузку ресурсов. Проверка конфигуратора подтверждает один canvas/renderer, запуск на той же площадке, управление мышью и касаниями, паузу, сброс, переключение камер, восстановление ракурса по кнопке и Escape, сохранение ночного режима, мобильную компоновку и освобождение игры при переходе в 2D:

```sh
node scripts/test-rc-browser.mjs
node scripts/test-configurator-rc-browser.mjs
```

Можно задать `RC_GAME_URL` для отдельной игры, `RC_CONFIGURATOR_URL` для конфигуратора и `RC_CDP_URL` для Chrome. Профиль тестового Chrome не размещайте в репозитории: Vite не должен отслеживать его служебные файлы. Скриншоты сохраняются в `.impeccable/review/rc-game-*.png` и `facade-rc-*.png`. После проверки закройте отдельный тестовый Chrome.

### Адаптивная графика

Профили выбираются по типу указателя, доступным сведениям о памяти и ядрах. Во время заезда устойчивые интервалы кадров более 24 мс в течение 3 секунд понижают качество; загрузка, пауза и скрытая вкладка исключены. Профиль не повышается до пересоздания сцены, чтобы избежать скачков качества. Физика продолжает работать фиксированным шагом 1/120 секунды.

| Профиль | Максимальный DPR | Тени двора | Тени здания |
| --- | --- | --- | --- |
| Высокий | 1,75 | 2048 | 2048 |
| Сбалансированный | 1,25 | 1024 | 1024 |
| Экономный | 1 | 1024 | 512 |

Для телефонов используются `ram-trx-mobile.glb` (25 691 треугольник, 1 419 020 байт) и `ram-trx-far.glb` (12 604 треугольника, 793 444 байта). Вместе это на 54% меньше исходной загрузки 4 841 864 байта. Полная модель сохраняется для близкого вида на мощных устройствах. Дальний вариант включается при размере машинки менее 180 экранных пикселей; возврат происходит выше 220 пикселей. Колёса, окраска и физические размеры совпадают. Для собственного `vehicleUrl` автоматическая подстановка файлов не выполняется.

Производные модели воспроизводятся командой `node scripts/build-trx-lods.mjs`; авторство и лицензия исходной RAM TRX сохраняются. Встраиваемая сборка копирует оба LOD-файла рядом с модулем. `npm run test:trx-asset` проверяет модели, переключение детализации, освобождение ресурсов, профили качества и инстансинг фасада.

Текстуры штукатурки, кровли и дерева создаются локально (512×512), используют mipmaps и не требуют сетевых изображений. Затемнение проёмов запекается в карту AO. Непрозрачные повторяющиеся детали фасада объединены в InstancedMesh; имена исходных объектов сохранены для привязок и столкновений. Стекло использует прозрачность и отражения без дополнительного прохода преломления всей сцены. Измеренная экономия — 64–89 вызовов отрисовки непрозрачных деталей за проход в зависимости от фасада. Это не оценка прироста FPS на реальном телефоне.
